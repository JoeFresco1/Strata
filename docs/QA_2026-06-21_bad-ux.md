# Strata QA Notes: Bad UX

Date: 2026-06-21
Scope: Localhost QA pass across Layer 0, Layer 1, and Layer 2
Environment: `http://127.0.0.1:5173` with local API on `http://127.0.0.1:8000`
Method: Browser-based manual pass only. No fixes applied.

## 1. Published projects still use draft/publish language on Layer 0

- Surface: Published project `Deep Research Smoke 2026-06-17` on the `Layer 0` tab
- Repro:
  1. Open the published project from the library.
  2. Land on `Layer 0`.
  3. Read the helper copy under Plan mode and the CTA area.
- Observed:
  - The page still says `The draft brief updates continuously, but Layer 1 stays locked until you publish.`
  - `Publish to Layer 1` is still visible even though the brief is already `published`.
- Why this is bad UX:
  - The state messaging does not match the actual project state.
  - It makes the page feel unreliable before the user even starts working.

## 2. Generate tab uses misleading empty-state copy

- Surface: Published project `Deep Research Smoke 2026-06-17` on the `Generate` tab
- Repro:
  1. Open the published project.
  2. Open `Generate`.
- Observed:
  - `Broaden Layer 1` is enabled.
  - Layer 2 sections say `No eligible items yet.`
  - The same project already has 3 Layer 1 pillars in Review and Tree.
- Why this is bad UX:
  - The current copy reads like the project has no usable Layer 1 output at all.
  - A more accurate explanation would likely mention review status or that no pillars are `kept` yet.

## 3. Export tab exposes raw internal JSON directly in the UI

- Surface: Published project `Deep Research Smoke 2026-06-17` on `Export`
- Repro:
  1. Open the published project.
  2. Open `Export`.
- Observed:
  - Large raw JSON blobs are rendered under `Generation Memory` and `Layer 1 Quarantine`.
  - The page becomes a wall of internals instead of a focused export workflow.
- Why this is bad UX:
  - The tab is visually noisy and hard to scan.
  - Internal memory payloads overshadow the actual export actions.
  - This feels more like a debug dump than a production workflow.

## 4. Export action gives little to no user feedback

- Surface: Published project `Deep Research Smoke 2026-06-17` on `Export`
- Repro:
  1. Click `Export Markdown and JSON`.
  2. Stay on the page and watch for download or confirmation feedback.
- Observed:
  - No visible confirmation appeared in the UI.
  - No browser download was triggered.
  - Files were written to the repo `exports/` folder, but the UI did not communicate that.
- Why this is bad UX:
  - The action looks like a no-op unless the user already knows to inspect the filesystem.
  - A success toast, output path, or recent-export card would reduce confusion immediately.

## 5. Competitive Intelligence starts blank even when the brief already knows competitors

- Surface: Published project `Deep Research Smoke 2026-06-17` on `Competitive Intelligence`
- Repro:
  1. Open the published project.
  2. Open `Layer 0` and note the captured competitors in the brief snapshot.
  3. Open `Competitive Intelligence`.
- Observed:
  - `Known Competitors` is blank in Competitive Intelligence.
  - The tab tells the user to add competitors to start the manual matrix.
- Why this is bad UX:
  - The product already knows competitors elsewhere in the same project.
  - The user has to mentally reconcile two sources of truth.

## 6. Project library gets noisy fast when there are multiple near-identical projects

- Surface: Project Library
- Repro:
  1. Open the root library.
  2. Scan the repeated `Embedding Smoke` cards.
- Observed:
  - Repeated cards with the same title are hard to distinguish quickly.
  - The created timestamp is present, but it is not enough visual differentiation on first scan.
- Why this is bad UX:
  - Selecting the correct project becomes slower than it should be.
  - A stronger subtitle, last-updated signal, or richer status badge would help a lot.
