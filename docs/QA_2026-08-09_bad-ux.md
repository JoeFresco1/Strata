# Strata QA Notes: Bad UX

Date: 2026-08-09

Scope: Post-merge browser QA on current `main` across Project Library, Map, Layer 0, Layer 1, Layer 2, Layer 3, Export, Analytics, Project Settings, and Assistant

Environment: Production frontend served from `http://127.0.0.1:8010` against an isolated disposable SQLite database

Method: Playwright desktop (`1440x1000`) and mobile (`390x844`) traversal, screenshots, visible-control labeling checks, viewport-overflow checks, browser/network diagnostics, API health checks, and manual screenshot review. No product fixes applied.

## Summary

- 52 automated browser assertions passed.
- No JavaScript errors, page errors, failed requests, HTTP 4xx/5xx responses, unlabeled visible buttons, or page-level horizontal overflow were observed.
- Two UX findings remain: one medium-priority responsive-layout defect and one lower-priority runtime-status discoverability issue.

## 1. Mobile Project Library leaves a large dead zone between search and filters

- Priority: P2
- Surface: Project Library at `390x844`
- Repro:
  1. Open Strata at a mobile viewport.
  2. Remain on the Project Library.
  3. Compare the position of the search field with the `View`, `Sort`, and primary-action controls.
- Observed:
  - Roughly a full mobile screen of empty vertical space appears after the search field.
  - `View`, `Sort`, `Create new project`, and `Import` are pushed well below the fold.
  - The responsive rule changes `.library-filter-bar` to a column, but `.project-search-wrap` retains its desktop `flex: 1 1 420px` basis and becomes an oversized vertical flex item.
- Impact:
  - The most important project-management controls look missing until the user scrolls through empty space.
  - The landing page feels broken on a phone even though the controls eventually work.
- Evidence: `.runtime/postmerge-qa-20260809-1540/evidence/mobile-library.png`
- Suggested direction: Reset the mobile search wrapper's flex basis or flex growth so its height follows the input.

## 2. The offline-model warning is hidden in the collapsed navigation rail

- Priority: P3
- Surface: Project Library and project workspace on initial load
- Repro:
  1. Start Strata while the configured local model provider is unavailable.
  2. Load the Project Library with the navigation rail in its default collapsed state.
  3. Expand the hamburger menu.
- Observed:
  - The API health response accurately reports `ok: false`.
  - The expanded rail accurately says `Local model offline. Generation and research will wait until llama.cpp is available.`
  - The default collapsed surface shows no equivalent warning, while model-backed controls remain discoverable throughout the workspace.
- Impact:
  - A user can enter the workflow without knowing generation, research, and assistant operations cannot currently complete.
  - The eventual provider failure may feel like a feature regression rather than an environment state.
- Evidence: `.runtime/postmerge-qa-20260809-1540/evidence/desktop-library.png` and `.runtime/postmerge-qa-20260809-1540/evidence/desktop-library-menu-open.png`
- Suggested direction: Surface a compact global offline indicator outside the expanded rail, without turning the normal workspace into a persistent error wall.

## Clean surfaces observed

- The full workflow tab bar reported coherent Published, Complete, Needs Review, and locked/available states.
- Map, Layer 0, Layer 1, Layer 2, Layer 3, Export, Analytics, Project Settings, and Assistant rendered without page-level overflow or unlabeled visible buttons.
- The Assistant opened as a labeled complementary panel and closed from its visible `Close` control.
- The Create Project dialog opened, trapped its task visually, disabled empty submission, and closed cleanly.
