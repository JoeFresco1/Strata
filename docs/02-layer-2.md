# Layer 2 Feature Graph

Layer 2 is a controlled, graph-native descent from approved Layer 1 pillars.

## Generation contract

- Expand only pillars the user kept or prioritized.
- Discover pillar-specific coverage families before or during generation.
- Generate concrete product capabilities, not pages, endpoints, database tables, tasks, or Layer 1-sized modules.
- Give each feature one owner pillar while allowing explicit cross-pillar relationships.
- Continue only while meaningful in-scope coverage remains and novelty has not saturated.

## Canonical Layer 2 entities

- raw candidates with model, lens, round, and pillar provenance
- canonical features
- aliases
- pillar affinities
- feature relationships
- coverage-family state
- ambiguity and integrity review signals
- shared concerns
- negative-cache entries
- review actions
- competitor evidence and research-run provenance

## Review behavior

- Candidate and ambiguous features remain reviewable rather than being silently deleted.
- Users can keep, cut, mark for review, merge, rename, reprioritize, and approve features.
- Duplicate recommendations and graph relationships are separate decisions.
- Rejected and merged-away concepts remain available as anti-rediscovery memory.
- Competitive evidence is advisory and cited; it does not automatically decide product scope.
